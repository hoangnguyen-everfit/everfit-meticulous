Headline: we changed one shared component and Meticulous listed every screen that renders it — no manual "find usages". This is the regression class that unit tests and manual review routinely miss.

Two lessons that decide success on everfit-react

Lesson 1 · Auth

Protected routes need "replay-safe" handling

Pages behind login redirect to /login during replay (no valid token) — so Meticulous captures the login page instead of the real one, and changes go undetected.

✓ Fixed by making the auth guard replay-aware.

Lesson 2 · Defensive code

Replay-time code must never throw

An unguarded call on page load crashed the whole app to an error page on every route. Meticulous then compared error-page vs error-page and reported "no differences".

✓ Fixed with feature-detection + try/catch.

⚠️ Both produce the same trap: a misleading "zero differences" that looks like a passing check but means the page was never tested. Rollout must verify replay renders the real UI — not just trust a green check.

Cost, performance & limits

Cost & performance

  • License: no public pricing; indicative ~$2,086/yr tiered by headcount (ranger.net, a competitor) → confirm with vendor.
  • Integration: ~1–2 engineer-days for the first workflow.
  • Maintenance: low — tests auto-generate & self-maintain.
  • Speed: ~60s CI build; 38–58 screens back in minutes; 0 flakes.

Where it is blind

  • Only tests real recorded flows — new/unused flows aren't covered.
  • Difference-detection, not assertions — a human approves each diff.
  • Backend is mocked → frontend behavior only.
  • Needs a baseline on main and sessions from real non-prod usage.
