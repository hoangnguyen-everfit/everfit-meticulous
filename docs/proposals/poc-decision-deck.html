02 · There's a different way

Record real sessions → on each PR replay them on old & new code → screenshot after every step → flag what changed for us to approve.

No test code No baseline upkeep No flaky failures

The tool is called Meticulous. That sentence is the whole mental model — the rest is detail.

03 · Straight talk — what it does NOT do

The limits, up front.

  • Frontend only
  • Mocks the backend → it won't test real business logic or the DB
  • If logic never shows in the UI, it can't catch it
  • Needs real sessions to build coverage → brand-new flows aren't covered yet
It does not replace Playwright for our critical flows — the two complement each other.

04 · The important part

Record → Replay → Diff

Switch to a real PR. Deliberately break a shared component so it breaks another page — and watch it get caught, live.

▶ open the browser — don't narrate slides here

05 · What's in it for you

Not "the company saves money" —
you get your time back.

  • Less UI test writing & maintenance
  • See the impact of a change before you merge
  • Fewer post-merge breakages — fewer "it's broken in prod" pings
  • No more flaky CI — trust the green check again
  • Refactor with confidence

06 · Proposed pilot

Small, controlled, measurable.

Scope
1 repo / a few flows keep the blast radius small
Duration
2–3 weeks time-boxed
Owner
One clear owner someone accountable for the trial
Success criteria (set now)
≥ N real regressions caught · low false-positives · devs feel it saves time

Safety & the way out

Low-risk by design.

Security

  • Recorded sessions can contain tokens/headers
  • So: enable in non-production only
  • Add only trusted people to the org

Exit plan

  • Not a fit? Remove it in 10 minutes
  • No test code to rip out — it's just a script + a CI check
  • No lock-in commitment to start

The only question today

Do we run the pilot —
yes or no?

If yes: this week we lock the repo, the owner, and the success criteria. If no: we've lost nothing but 35 minutes.
