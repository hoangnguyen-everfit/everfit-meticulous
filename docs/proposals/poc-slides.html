01

The idea

First, what problem are we solving — and how does this tool think about it?

The everyday problem

You fix one thing…
and quietly break another.

  • We change the UI all the time — new features, tweaks, refactors
  • A change in one place can break a screen somewhere elseespecially shared pieces reused across pages
  • Today we often find out late — from QA, or worse, from users

One word to know

A "regression".

Something that used to work, and your latest change accidentally broke.

"Regression testing" just means: checking that your change didn't break anything that was working before. Meticulous automates exactly this — for the frontend.

Two ways to do it

Write tests by hand…
or let the tool learn from real use.

The traditional way

Hand-written test scripts

Slow to write, brittle, and someone has to update them every time the UI changes. Coverage is always behind.

Meticulous

Learns from real sessions

No test code to write or maintain. It watches how people actually use the app and turns that into tests automatically.

How it works — in plain terms

Like a security camera + spot-the-difference.

Step 1 · Record

Watch real users

A small script quietly records real sessions in our test environments — clicks, typing, everything.

Step 2 · Replay

Re-run them on new code

When you open a pull request, it re-plays those same sessions on the old and the new version.

Step 3 · Compare

Flag what changed

It puts the before/after screenshots side by side and highlights any difference for a human to approve.

If you remember one thing

It tests what real users do —
and shows you exactly what your change altered, on every screen.

You stay in control: each difference is something a person reviews and approves or rejects.

In practice

We didn't just read about it — we tried it ourselves and watched what it caught.

Our hands-on trial

We ran it on a real app,
through real pull requests.

  • Built a small app on our own tech, connected Meticulous
  • Used it like a normal user to record a few sessions
  • Opened pull requests with real changes — and watched what it flagged

The moment it clicked

Change one shared piece →
it finds every screen it lives on.

What the developer did

"Just tweaking one banner"

Edited a single shared component — without remembering everywhere it appears.

What Meticulous showed

Flagged on 2 different screens

It surfaced the change on both the login and dashboard pages — automatically, with no one telling it where to look.

It also caught a real bug

A crash our other tests
completely missed.

One change made the app fail to load for real users. Our normal tests stayed green — but replaying an actual user session caught it immediately. That's the kind of bug that otherwise reaches production.
